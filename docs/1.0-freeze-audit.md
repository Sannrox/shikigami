# 1.0 freeze audit (research closeout)

- Status: **Recommendation recorded**
- Date: 2026-07-26
- Resolves: research [#109](https://github.com/Sannrox/shikigami/issues/109)
- Contract authority: [ADR 0004](decisions/0004-v1-contract.md) (medium 1.0)
- Inputs: [#107](https://github.com/Sannrox/shikigami/issues/107) CI embed smoke,
  [#108](https://github.com/Sannrox/shikigami/issues/108) host-proof docs,
  crate `0.2.0`, tags `v0.1.0` / `v0.2.0`

## Decision question (restated)

Against the **accepted** medium 1.0 contract, is a 1.0 tag responsible now,
and if not, what ordered gaps remain?

This audit does **not** reopen thin vs medium vs broad.

## Primary recommendation

**Originally (audit open): no-go** until external embed smoke existed.

**Update (2026-07-26, #113):** external offline embed smoke is **met** via
[`Sannrox/shikigami-embed-smoke`](https://github.com/Sannrox/shikigami-embed-smoke)
(out-of-tree consumer, git tag `v0.2.0`, CI `cargo run --locked`, no plane).

Remaining path to tag `v1.0.0` is the **release chore** only
([#114](https://github.com/Sannrox/shikigami/issues/114)): version `1.0.0`,
CHANGELOG freeze notes, tag, release workflow. Medium contract surfaces were
already met in-tree at the original audit.

## Hypotheses evaluated

| # | Hypothesis | Result |
| --- | --- | --- |
| 1 | Ready soon after CI + docs only | **Rejected** — external embed still required by ADR consequences |
| 2 | Gap: external embed | **Accepted** — sole hard product gap for 1.0 checklist |
| 3 | Gap: contract drift | **Rejected as blocker** — freeze tables (#108) match medium contract; MCP/hooks/cost correctly marked evolving/host-only |
| 4 | Gap: governed path proof | **Rejected as blocker** — offline + ignored live + nightly matches “offline first-class” medium scope |
| 5 | Defer 1.0 because 0.2.0 surfaces churn | **Soft support** — stay on `0.x` until external proof; do not freeze MCP/TUI as core |
